# 就活メモ整理AIエージェント 要件定義書

**バージョン**: 1.0  
**作成日**: 2026-09-09  
**ステータス**: Draft

---

## 1. プロジェクト概要

### 1.1 目的

就活中に発生する大量のメモ・情報（説明会メモ、面接準備、企業研究など）を一元管理し、情報の散在・紛失を防ぐ。AIを活用して自動分類・要約を行い、必要な情報を素早く検索・参照できる環境を提供する。

### 1.2 背景・課題

- 手書きメモ、スマホメモ、コピペ情報が複数場所に散在している
- どの企業の情報かを後から探すのに時間がかかる
- 面接前に関連情報をまとめ直す作業が毎回発生する
- スマホとPCどちらからでもアクセスしたい

### 1.3 ターゲットユーザー

就職活動中の学生・転職活動中の社会人（個人利用）

---

## 2. スコープ

### 2.1 MVP（最小実用製品）

初期リリースで提供する中核機能。実用性の検証を目的とする。

### 2.2 将来拡張

MVPの検証後、ユーザーの利用状況に応じて追加する機能。

## 3. 機能要件

### 3.1 MVP機能

#### F-01 コピペ情報の取り込み

| 項目 | 内容 |
|------|------|
| 概要 | テキストをコピペまたは直接入力してメモを登録する |
| 入力 | テキスト（企業名・URL・メモ本文など任意形式） |
| 出力 | 構造化されたメモエントリ（後述のデータモデル参照） |
| 優先度 | 必須 |

- Webフォームまたは CLI からテキストを貼り付けて登録できること
- 登録時に企業名・メモ種別を任意入力できること（未入力時はAIが推定）

#### F-02 AIによる自動分類

| 項目 | 内容 |
|------|------|
| 概要 | 入力されたメモをAIがカテゴリに自動分類する |
| カテゴリ例 | 企業研究 / 説明会 / OB訪問 / ES・履歴書 / 面接 / 内定・選考結果 / その他 |
| 優先度 | 必須 |

- 分類結果はユーザーが手動で修正できること
- 企業名が不明な場合、AIが本文から推定して付与すること

#### F-03 AIによる要約

| 項目 | 内容 |
|------|------|
| 概要 | 長いメモをAIが自動で要約する |
| 出力 | 3〜5行の箇条書き要約 |
| 優先度 | 必須 |

- 要約は元のメモと並べて表示されること
- ユーザーが要約を編集・削除できること

#### F-04 Googleスプレッドシートへの保存

| 項目 | 内容 |
|------|------|
| 概要 | メモデータをGoogleスプレッドシートに書き込み・同期する |
| 優先度 | 必須 |

- 1行1メモ形式でスプレッドシートに保存すること
- 保存カラム：登録日時 / 企業名 / カテゴリ / 要約 / 本文 / タグ / ソース種別
- Google Sheets API（サービスアカウント認証）を使用すること
- 重複登録を防ぐためにメモIDで管理すること

#### F-05 スマホ閲覧

| 項目 | 内容 |
|------|------|
| 概要 | スマホブラウザからメモ一覧・詳細を閲覧できる |
| 優先度 | 必須 |

- レスポンシブデザイン対応のWebUIを提供すること
- 企業名・カテゴリでフィルタリングできること
- MVPでは閲覧・検索のみ（スマホからの新規登録は将来拡張）

#### F-06 自然言語検索

| 項目 | 内容 |
|------|------|
| 概要 | 「〇〇社の面接でどんなことを聞かれたか」のような自然言語クエリで検索できる |
| 優先度 | 必須 |

- ベクトル検索（Embedding）または全文検索でメモを検索すること
- 検索結果は関連度順で表示すること
- MVP では簡易キーワード検索＋AIによる回答生成でも可

---

### 3.2 将来拡張機能

#### F-07 OCRによる紙メモ取り込み

| 項目 | 内容 |
|------|------|
| 概要 | 手書きメモや印刷物をカメラ撮影してテキスト化・登録する |
| 想定手段 | Google Vision API または Tesseract OCR |
| 優先度 | 将来拡張 |

- スマホカメラから直接画像アップロードできること
- OCR結果をユーザーが確認・修正してから保存できること

#### F-08 スマホからの新規登録

- スマホブラウザからメモを新規作成・編集できること
- 音声入力との連携も検討

#### F-09 リマインダー・アクション管理

- 「〇〇社 ES締切 XX日」などの締切をメモから抽出してリマインドする
- Googleカレンダー連携

#### F-10 企業ページ自動スクレイピング

- 企業URLを登録すると採用情報を自動取得・要約する

#### F-11 面接対策Q&A生成

- 蓄積されたメモをもとに想定質問と回答案をAIが生成する

#### F-12 エクスポート機能

- PDF・Markdownへのエクスポート
- 企業別・カテゴリ別のレポート生成

## 4. 非機能要件

### 4.1 パフォーマンス

- メモ登録（分類・要約含む）：30秒以内に完了
- 検索：5秒以内に結果表示

### 4.2 セキュリティ

- 就活情報は個人の機密情報として扱う
- Google OAuth またはサービスアカウントの認証情報をコードに直書きしない（環境変数管理）
- スプレッドシートは非公開設定を維持すること

### 4.3 可用性

- 個人利用のため高可用性は必須としない
- ローカル実行またはクラウド（GCP / Railway / Renderなど）での動作を許容

### 4.4 スケーラビリティ

- メモ件数：MVP期間中は最大500件程度を想定
- 将来的に1,000件超でも検索性能が劣化しないこと

## 5. データモデル（メモエントリ）

```
{
  "id": "uuid",
  "created_at": "ISO8601",
  "updated_at": "ISO8601",
  "company_name": "株式会社〇〇",
  "category": "面接 | 企業研究 | 説明会 | OB訪問 | ES・履歴書 | 選考結果 | その他",
  "tags": ["技術職", "東京", "一次面接"],
  "source_type": "paste | ocr | manual",
  "raw_text": "元のメモ本文",
  "summary": "AIによる要約",
  "memo_date": "YYYY-MM-DD（メモの日付、登録日と異なる場合）"
}
```

## 6. システム構成（MVP案）

```
[ユーザー]
    │
    ├─ PC: Webフォーム or CLI
    └─ スマホ: Webブラウザ（閲覧・検索）
         │
         ▼
[Webアプリ / APIサーバー]
  ├─ テキスト受け付け
  ├─ AI処理（分類・要約・検索）← OpenAI API or Gemini API
  └─ データ保存 ← Google Sheets API
         │
         ▼
[Googleスプレッドシート]（永続ストレージ）
```

**技術スタック候補（MVP）**

| レイヤー | 候補 |
|----------|------|
| バックエンド | Python (FastAPI) |
| フロントエンド | Next.js または Streamlit |
| AI | OpenAI API (GPT-4o) または Google Gemini API |
| ストレージ | Google Sheets API |
| ホスティング | ローカル or Render / Railway |

## 7. ユーザーストーリー（MVP）

1. **説明会後のメモ登録**  
   「説明会で取ったメモをコピペしたら、自動で企業名が付いて『説明会』カテゴリに分類され、要約も生成された」

2. **面接前の情報確認**  
   「『〇〇社について教えて』と検索したら、過去の説明会メモ・企業研究・OB訪問メモがまとめて表示された」

3. **移動中のスマホ閲覧**  
   「電車の中でスマホから企業一覧を確認し、面接の企業のメモを読み返した」

---

## 8. 受け入れ条件（MVP完了基準）

- [ ] テキストをコピペしてメモを登録できる
- [ ] AIが企業名・カテゴリを自動付与する
- [ ] AIが3行以上の要約を生成する
- [ ] Googleスプレッドシートにデータが保存される
- [ ] スマホブラウザでメモ一覧を閲覧できる
- [ ] 自然言語またはキーワードでメモを検索できる
- [ ] 環境変数でAPIキーを管理しており、コード内に秘密情報がない
